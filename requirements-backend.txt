# requirements-backend.txt
# -------------------------
# Runtime closure for the SmartSurround Flask backend running in REMOTE
# inference mode (ROAD_DAMAGE_INFERENCE_MODE=remote), as used by the Phase 5
# docker-compose stack.
#
# WHY THIS FILE EXISTS INSTEAD OF requirements.txt
# ------------------------------------------------
# requirements.txt is the host/DEV closure and pins ultralytics, which pulls
# torch + torchvision + OpenCV. Inside Compose the backend NEVER imports them:
#
#   hazard.py imports `detector` only when INFERENCE_MODE == "local", and
#   detector.py is the only module in the Flask import graph that touches
#   ultralytics/torch/cv2. In remote mode the transport is plain `requests`.
#
# Verified by static import scan of the Flask import graph
# (app.py -> db, hazard, hazard_types, letter_generator, corroboration,
#  authority_routing, email_driver, geocode, cluster_service):
#   flask, dotenv, requests, reportlab, PIL, resend  -- nothing heavier.
#
# Installing ultralytics here would drag ~2 GB of CUDA torch wheels into a
# container that can never call them, which matters because this machine has
# only ~4.8 GB free on C: and the ML image is already 2.61 GB.
#
# This file is INTENTIONALLY NOT a replacement for requirements.txt. The host
# dev environment still uses requirements.txt so that local-mode inference and
# the Phase 1 golden baseline are unchanged. Model logic, detector.py and
# ml/requirements-ml.txt are untouched by this file.
#
# There is NO runtime pip install in the backend image, so no autoinstall /
# dependency-mutation hazard exists here at all (see ml/requirements-ml.txt for
# the ultralytics/pi-heif discussion that applies to the ML image only).
